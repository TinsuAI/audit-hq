# Phương án sản phẩm demo Audit-HQ

**Ngày:** 2026-05-21
**Trigger:** HQ đã duyệt nguyên tắc đề án v10. Trọng Tín gửi dữ liệu nền (622 file, 6 DN thực).
**Status:** Đã duyệt (2026-05-21). Quyết định: approach A (dữ liệu thực anonymize), repo `audit-hq-mvp`, deploy `audit-hq-demo.tinsu.ai`, basic-auth, DN_005 sạch = HONG_PHUC.

## 1. Tóm tắt điều hành

- Demo = **16 kiểm tra MVP** (Nhóm 1-6 ✅) chạy được trên dữ liệu thực 6 DN đã ẩn danh.
- Stack: **Python 3.12 + FastAPI + Jinja2 + pandas + SQLite/PostgreSQL + Docker** (đồng bộ stack `BCQT-System` của Trọng Tín — reuse parser, auth, templates).
- Repo MVP **mới hoàn toàn** (`audit-hq-mvp`), tách khỏi repo đề án này.
- Thời gian: **10 tuần** theo §7 — có thể **rút còn 8 tuần** nếu dùng dữ liệu thực đã anonymize thay vì sim (xem mục 4).
- Deploy: Tinsu VPS (same host `tinsu`), Cloudflare Tunnel route mới `audit-hq-demo.tinsu.ai` (basic-auth hoặc IP whitelist tùy ý HQ).

## 2. Stack kỹ thuật

| Lớp | Lựa chọn | Lý do |
|---|---|---|
| Ngôn ngữ | Python 3.12+ | Đã trong đề án §5.2; Tinsu chuẩn |
| Web | FastAPI + Jinja2 (server-side) | Như BCQT-System; không SPA cho đỡ phức tạp |

| CI/CD | Manual `make publish` ban đầu; GitHub Actions sau khi ổn | Tiết kiệm tuần 1 |
| Test | pytest | Unit test mỗi rule riêng + integration |

### Tuần 7 — Anonymize 5 DN demo

- Script `anonymize.py`:
  - Map tên DN thực → DN_001 ... DN_005 theo §6.1 đề án.
  - Thay MST, tên NCC bằng dạng ngẫu nhiên ổn định (seed cố định để tái lập).
  - Giữ mã HS, mã loại hình, số lượng/giá trị (có thể scale × hằng số).
  - Output `data/anonymized/<DN_xxx>/<năm>/...`.
- **Mapping 5 DN demo (đã chốt 2026-05-21):**
  - **DN_001** (điện tử HS 85, DNCX E11/E42, 4 năm) ← **GROWATT** (3 năm 2023-2025) hoặc cân nhắc dùng HONG_AN nếu ngành thực HONG_AN khớp hơn — verify ở tuần 2 khi đã đọc được tên hàng.
  - **DN_002** (cơ khí HS 84, DNCX, 3 năm) ← **KIM_LONG** (2 năm) hoặc **HIEP_QUANG** một phần (chọn 3 năm gần nhất 2023-2025).
  - **DN_003** (dệt may HS 61, SXXK E31/E62, 4 năm) ← **HONG_AN** (8 năm 2018-2025) — chọn 4 năm cuối, case study cúc áo C4.4.
  - **DN_004** (hoá chất HS 39, DNCX, 3 năm) ← **DO_THANH** (3 năm 2023-2025).
  - **DN_005** (sạch, 3 năm) ← **HONG_PHUC** (2 năm 2024-2025) — cố tình KHÔNG inject sai phạm; nếu trong dữ liệu thực có phát hiện thì giữ ở mức "thông tin" (🔵).
  - **HIEP_QUANG dự bị** — không dùng demo, giữ trong `data/raw/` để regression test (data lâu năm 2015-2025, phục vụ test rule liên kỳ Nhóm 6).
- **Deliverable:** 5 DN anonymized chạy được toàn bộ 16 check.

## 5. Rủi ro và mitigation

| Rủi ro | Mức | Mitigation |
|---|---|---|
| Schema Excel của DN khác nhau (HONG_AN khác GROWATT) | 🔴 Cao | Adapter pattern — mỗi DN có thể có sub-adapter; chuẩn hoá ở tầng 1 |
| `.xls` cũ (Excel 97-2003) — xlrd hỗ trợ kém | 🟡 TB | Convert `.xls` → `.xlsx` qua libreoffice ở pipeline ingest; cache |
| Dữ liệu BCCT export từ ECUS có cell merged, header phức tạp | 🟡 TB | Test trên file lớn nhất (HONG_AN BaoCaoHangChiTiet XNK 2024 = 11MB, ~10k dòng) ngay tuần 2 |
| Tên DN/MST trong nhiều file không nhất quán (chữ thường/HOA, có dấu/không dấu) | 🟡 TB | Chuẩn hoá ở adapter (lower + bỏ dấu + strip) |
| Anonymize làm lệch số liệu → check sai | 🔴 Cao | Chỉ scale hằng số tuyến tính nếu cần; KHÔNG random từng dòng |
| HQ muốn check khác 16 MVP đề xuất | 🟡 TB | Catalog mở rộng được (§2.3) — thêm 1 check ~1-2 ngày dev |
| LLM API rate limit / cost | 🔵 Thấp | Cache hard, fallback heuristics, dùng đúng ở §5.3 (chuẩn hoá tên) |
| Server Tinsu down trong tuần demo | 🟡 TB | Backup local Docker compose; demo offline được trên laptop |
